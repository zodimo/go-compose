**Generated:** 2026-04-05

## OVERVIEW

Go implementation of Jetpack Compose Material 3 API using Gio UI framework. Declarative UI with `Composable func(Composer) Composer` pattern.

**Stack:** Go 1.24.4 + gioui.org (rendering) + custom go-* packages (state, flow, etc.)

## STRUCTURE

```
go-compose/
├── cmd/go-compose/       # CLI tool (build/serve commands)
├── cmd/demo/             # 50+ demo apps (kitchen sink showcase)
├── compose/              # Core framework (Material 3 + Foundation)
│   ├── material3/        # Material 3 components (buttons, cards, dialogs...)
│   ├── foundation/       # Foundation (text, layout, lazy lists)
│   └── ui/               # UI primitives (graphics, text, modifiers)
├── internal/             # Implementation details (color, layout, composer)
├── modifiers/            # Modifier functions (size, padding, weight)
├── pkg/                  # Public API + utilities (api, flow, floatutils)
├── state/                # State management (MutableValue)
├── theme/                # Theming (color schemes, typography)
├── lifecycle/            # Frame lifecycle handling
└── runtime/              # Runtime support
```

## CONVENTIONS

### Alias Pattern (Non-Standard)

Project uses alias.go files to re-export types from implementation packages:

```go
// compose/foundation/next/text/alias.go
package text
import "github.com/zodimo/go-compose/compose/ui/next/text"
type TextStyle = text.TextStyle  // Re-export from impl
```

Why: API stability - public API can change implementation location.

### "next" Directory Pattern

Parallel implementations indicate newer/evolved APIs:
- compose/foundation/text/ <-> compose/foundation/next/text/
- compose/material3/button/ <-> compose/material3/next/button/
- compose/ui/text/ <-> compose/ui/next/text/

Convention: Work in next/ for new features; non-next/ may be deprecated.

### Composable Pattern

```go
type Composable func(Composer) Composer

// Usage: functions return Composable
func Button(onClick func(), content Composable) Composable {
    return func(c Composer) Composer {
        // compose implementation
        return c
    }
}

// Composition: use c.Sequence or nested calls
c = c.Sequence(
    Button(...),
    Text(...),
)(c)
```

### State Management

```go
// MutableValue - reactive state
value := state.MustRemember(c, "key", func() *state.MutableValue[int] {
    return state.NewMutableValue(0)
})
value.Set(42)
value.Get()  // -> 42
value.Subscribe(func(v int) { /* onChange */ })

// StateFlow - hot observable (from pkg/flow/)
sf := flow.NewMutableStateFlow(initialValue)
```

### Known Bugs (Documented in Code)

1. Tooltips on Clickables: compose/material3/tooltip/tooltip.go:108-112 - Tooltips don't work on Button/Clickable due to pointer event capture. Workaround: use pointer.PassOp or centralized hover manager.
2. Word Navigation: compose/foundation/next/text/widget/text.go:694-697 - Only whitespace-delimited; non-whitespace languages have counter-intuitive behavior.

## UNIQUE STYLES

### Modifier Chaining

```go
modifier := size.FillMax().Then(padding.All(16)).Then(background.Color(color.NRGBA{R: 255}))
```

### Control Flow Composables

```go
// Conditional rendering
c = c.When(condition, func() api.Composable {
    return Text("visible when true")
})

// Lazy conditional (predicate evaluated only if needed)
c = c.WhenLazy(condition, func() api.Composable { ... })

// Sequence combining multiple composables
c = c.Sequence(comp1, comp2, comp3)(c)
```
